# SyncTool

**把多个文件夹当成同一份数据来用：最新者胜出，旧版本进 `.backup`，随时按时间点还原。**

一个 Windows / Linux / macOS 的单文件命令行工具，C++17 编写，不依赖任何运行库或外部压缩软件。给它几个文件夹，它让它们变成同一份内容；给每个被替换的版本留一份可还原的备份。

| | |
|---|---|
| **同步** | `SyncTool sync A B C --min-level 1` —— 三份文件夹互相同步，谁的版本新就用谁的 |
| **备份** | 被替换的旧文件/旧目录自动进入各文件夹自己的 `.backup\<时间>\`，Windows 下自动隐藏 |
| **还原** | `SyncTool restore A --time 2026-10-25-22-26-13` —— 只还原一个文件夹，先删后复 |

## 功能

- **对等同步**：命令行列出的文件夹互为对等；每个最小单元取修改时间最新的版本，复制到所有文件夹。
- **最小保留目录层数**：`--min-level N` 时，深度为 `N+1` 的目录作为一个整体单元参与比较与替换；不设置时逐文件比较。例如 `--min-level 1` 表示深度 2 的目录（`root\a\b`，如 `C++\SyncTool`、`Kotlin\sms-forwarder`）各自整体替换；`--min-level 0` 才是 `root\a` 这一层。
- **同时间内容比对**：修改时间完全相同的单元不再直接跳过，而是比对内容哈希；哈希相同才跳过，不同则进入冲突队列，逐个询问使用哪个文件夹的版本作为源，或选择跳过。询问在独立线程进行，其他复制线程继续工作；多个冲突按顺序排队。
- **目录整体备份**：目录单元被替换时，旧目录打成 `.zip`（最快压缩档），并在 `manifest.txt` 中登记，还原时自动识别为目录。
- **`.backup`**：备份目录统一为 `.backup`；Windows 下自动设置隐藏属性；v1 的 `backup` 目录首次运行时会自动迁移。
- **先计划、后执行**：同步前完整扫描所有文件夹，算出"要复制什么、备份什么、删除什么"，写入系统临时目录的 JSON 计划文件，并用独占句柄占住它（防止被清理、防止同一组文件夹并发同步）。
- **进度可见**：扫描进度、预检汇总、执行总进度、当前操作、已处理数据量、速度与剩余时间。
- **磁盘空间预检**：按卷汇总"复制 + 备份估算 + 1 GB 余量"，空间不足直接中止，不会写满磁盘；运行中如果剩余空间低于 512 MB 也会立即停止。
- **并行复制**：`--jobs N` 多线程并行处理不同单元；目录 zip 改为流式写盘，内存占用与目录大小无关。
- **同步期间占用文件夹**：Windows 下以"共享读、独占写"打开各根目录并保持到结束，提示不要手动修改；子文件仍可能被其他程序写入（Windows 没有内核级强制目录锁），所以请把这条当作保护而不是绝对隔离。
- **安全兜底**：备份失败就跳过该单元，绝不先删后拷；备份成功才删除旧版本；Ctrl+C 会停止复制，并询问"保留本次备份以便下次继续"；如果选择不保留，再询问是否回滚本次已完成的更改（新增的删除、替换的从备份恢复）。退出码 130。
- **清理备份**：`clean` 可按序号选择一个或多个时间点清理，也支持 `--time`、`--all`，删除前显示占用并二次确认。
- **长路径**：Windows 下如果 `LongPathsEnabled` 未开启，会询问是否自动开启；确认后程序自己写注册表（需要时自动提权）并重启自身，让 `longPathAware` manifest 生效，不需要手动改注册表。
- **中文路径**：全程 UTF-8，Windows / Linux / macOS 的中文文件名与目录名都按原样同步。
- **排除规则**：`--exclude` 支持 `*` / `?`，可排除缓存、构建产物、`.git` 等不需要同步的内容。
- **跨平台**：Windows、Linux、macOS 三套单文件构建；GitHub Actions 自动编译并随 Release 发布。

## 快速开始

```bat
:: Windows：三个文件夹互相同步，第二层目录作为整体单元
SyncTool.exe sync D:\work E:\work-backup F:\work-mirror --min-level 1

:: 只预检，不改任何文件（会打印每个文件夹需要多少空间、每个操作是什么）
SyncTool.exe sync D:\work E:\work-backup --min-level 1 --dry-run

:: 看某个文件夹有哪些备份时间点
SyncTool.exe list D:\work

:: 还原到指定时间点（只还原一个文件夹；不写 --time 会列出序号让你选）
SyncTool.exe restore D:\work --time 2026-10-25-22-26-13

:: 清理备份：按序号多选，或直接指定时间点/全部
SyncTool.exe clean D:\work
SyncTool.exe clean D:\work --time 2026-10-25-22-26-13
SyncTool.exe clean D:\work --all --dry-run
```

```bash
# Linux / macOS 用法完全一致
./SyncTool sync ~/work /mnt/backup/work --min-level 1
./SyncTool restore ~/work
./SyncTool clean ~/work
```

不带 `--min-level` 时是**逐文件**比较；带 `--min-level 1` 时，深度 2 的目录（`root/a/b`，例如 `C++/SyncTool`）作为整体单元，任何一个文件更新就整体替换，旧目录打成 zip。`--min-level 0` 才是 `root/a` 这一层。

**同时间不同内容**：扫描后先比对哈希；如果哈希不同，会逐个列出各文件夹的大小和哈希前缀，输入序号选择源，输入 `0` 跳过。多个冲突排队询问，其他线程继续复制普通单元；`--yes` 会全部跳过冲突。

## 命令与参数

```
SyncTool sync <文件夹1> <文件夹2> [...] [选项]
SyncTool restore <文件夹> [--time <时间戳>] [--dry-run]
SyncTool list <文件夹>
SyncTool clean <文件夹> [--time <时间戳>|--all] [--dry-run] [--yes]
SyncTool help | --version
```

| 选项 | 说明 |
|---|---|
| `--min-level N` | 最小保留目录层数。深度 `N+1` 的目录作为整体单元；不设置 = 深度无限、逐文件比较 |
| `--jobs N` | 并行线程数（默认按 CPU，2–8；机械硬盘建议 2–4） |
| `--exclude <模式>` | 排除路径，可多次使用；支持 `*` / `?`，匹配相对路径或文件名。例：`--exclude "*/build/*" --exclude "*.tmp"` |
| `--dry-run` | 只扫描、预检、比对哈希、生成计划，不修改任何文件；会报告同时间冲突数量 |
| `--force` | 磁盘空间预检不足时仍继续（运行中的 512 MB 兜底仍生效） |
| `--yes` | 所有询问取默认值：冲突跳过、中断保留备份、长路径自动开启、清理确认 |
| `--no-long-paths` | 不自动开启 Windows 长路径支持 |
| `--no-hash-cache` | 不使用跨运行哈希缓存，每次都重新读取文件（最准确但更慢） |
| `--time <时间戳>` | 还原/清理指定时间点；不写则列出序号交互选择 |
| `--all` | `clean` 专用：清理全部时间点 |
| `--version` | 打印版本 |

时间点选择统一从 **1** 开始编号；`clean` 支持 `1,3` 这样的多选。

退出码：`0` 成功 / `1` 有错误 / `2` 空间不足中止 / `130` 被 Ctrl+C 中断。

## 备份结构

以 `root` 为例，某次同步时间 `2026-10-25-22-26-13`：

```
root\
  a\b\c\abc.txt                    同步后的最新文件
  a\b\c1\                          同步后的最新目录
  .backup\                         （Windows 隐藏）
    2026-10-25-22-26-13\
      a\b\c\abc.txt                被替换的旧文件，保留原相对路径
      a\b\c1.zip                   被替换的旧目录，快速压缩
      manifest.txt                 记录哪些 zip 是目录备份
      journal.jsonl                本次运行的变更日志（中断时保留，用于回滚）
```

- 文件备份：按原相对路径直接存放，还原时先删当前文件再复制回来。
- 目录备份：`<相对路径>.zip`，并在 `manifest.txt` 里登记；还原时删除整个目录再解压。
- 每次同步一个时间戳目录；同一秒重复自动加 `-2`、`-3`。
- 中断时默认保留本次备份和 `journal.jsonl`，下次运行会跳过已完成的单元继续；如果选择回滚，按 journal 删除本次新增、从备份恢复本次替换。
- `clean` 可按序号清理一个或多个时间点；清理后不可恢复。
- 根目录下的 `.backup` / `backup` 不参与同步。

## 工作原理

**阶段一 · 扫描**：并行扫描每个文件夹，跳过根级 `.backup`/`backup` 与符号链接，按 `--min-level` 把文件或目录归并成"单元"，记录每个单元在每个文件夹里的修改时间、大小和文件数。

**阶段二 · 预检与计划**：每个单元选时间最新的版本为胜者（时间相同则目录优先、参数靠前的文件夹优先）；对每个目标文件夹判断需要"新增、替换、跳过"。所有操作写入临时 JSON 计划，并做按卷的磁盘空间检查。

**阶段三 · 哈希比对**：对修改时间相同、类型相同的单元计算内容哈希（文件直接哈希；目录把路径、大小、文件哈希排序后汇总）。哈希相同则跳过；不同则进入冲突队列。哈希结果缓存在系统临时目录，后续同步不必重复读取大文件。

**阶段四 · 执行**：多线程并行处理普通单元；另有一个独立的冲突解析线程逐个询问同时间冲突。对每个需要替换的单元：

1. 写入 journal（`started`）；
2. 先备份旧版本：文件复制到 `.backup\<时间>\<相对路径>`，目录流式压缩成 `.zip` 并登记 manifest；
3. 备份失败 → 跳过该单元，**不删除任何东西**；
4. 备份成功 → 写 journal `backedUp` → 删除旧版本 → 复制胜者（保留原修改时间，避免下次误判为新）→ 写 journal `done`；
5. 每个文件复制完更新时间戳，目录单元整树复制。

**冲突询问**：列出每个文件夹的序号、大小和哈希前缀，输入序号选择源，输入 `0` 跳过。多个冲突排队，前一个回答完才出下一个；普通复制线程不受影响，至少有一个线程继续复制（除非普通操作已全部完成）。

**还原**：读取 `.backup\<时间>\`，按 `manifest.txt` 识别目录 zip；对每个备份条目先删除目标位置的当前文件/目录，再复制或解压回去。备份中不存在的路径不受影响。

**中断**：Ctrl+C 停止工作线程后询问是否保留本次备份；不保留时再询问是否回滚。回滚按 journal 逆序处理：新增的文件/目录删除，替换的从备份恢复。

## 安全设计

- **计划文件独占**：计划写在系统临时目录 `SyncTool/plan-<hash>.json`，用独占句柄打开；同一组文件夹不能并发同步，结束后（含 Ctrl+C）自动删除。
- **空间预检**：按卷汇总需求（备份按 zip 压缩后 85% 保守估算 + 1 GB 余量）；不足直接退出，避免半截文件。
- **运行中兜底**：剩余空间低于 512 MB 立即停止写入，已完成的单元有备份，可还原。
- **文件夹占用**：Windows 下打开根目录句柄（共享读、独占写），阻止重命名/删除与 Explorer 进入；这不是内核级强制锁，仍建议同步时不要修改目录。
- **路径安全**：解压时拒绝绝对路径、盘符和 `..`；不跟随符号链接，避免循环与越界。
- **中断安全**：Ctrl+C 设置取消标志，工作线程停止后询问"保留备份 / 回滚本次更改"；journal 记录每个单元的 `started / backedUp / done / failed`，回滚可精确恢复。
- **长路径安全**：Windows 构建内嵌 `longPathAware` manifest；`LongPathsEnabled` 未开启时询问并自动写入（必要时 UAC 提权），随后重启自身生效。
- **哈希缓存**：同时间比对的内容哈希缓存在系统临时目录，按路径+大小+修改时间失效；不污染被同步目录。



## 常见问题

**时间一样会复制吗？**
会先比对内容哈希：哈希相同才跳过；哈希不同会列出各文件夹让你选源，或输入 `0` 跳过。`--yes` 时冲突自动跳过。

**为什么同步后备份目录很大？**
目录单元是整棵子树备份，zip 里保存了所有文件。确认无误后可以用 `SyncTool clean <文件夹>` 按序号清理旧时间点；工具不再自动删除。

**机械硬盘同步很慢？**
`--jobs` 降到 2–4，避免多线程在同一个盘上互相寻道。大量小文件的目录（如 msys2、node_modules）本身就会慢，扫描和压缩都需要时间。第一次同步还要计算同时间单元哈希，之后有缓存会快很多。

**哈希缓存会不会漏判？**
缓存按“路径 + 大小 + 修改时间”失效；正常编辑、复制都会改变修改时间，工具自己写入后也会主动清除对应缓存。只有内容在大小和修改时间都完全不变的情况下被改写（少见）才可能漏判，此时加 `--no-hash-cache` 强制每次重新读取文件。

**可以排除缓存吗？**
可以，例如：

```bat
SyncTool.exe sync A B C --min-level 1 --exclude "*/node_modules/*" --exclude "*/.git/*" --exclude "*/build/*"
```

**同步时能继续用这些文件夹吗？**
不要。Windows 下工具会占用根目录，但子文件仍可能被其他程序改写；同步中修改可能导致这一轮结果不一致，请等结束。

**Ctrl+C 后备份还在吗？**
会先问"保留本次备份结果以便下次继续"；默认保留。选不保留时会再问是否回滚本次已完成的更改。回滚失败时会保留备份目录，方便手动处理。

**Windows 长路径需要手动开吗？**
不需要。程序检测到 `LongPathsEnabled` 未开启会询问，确认后自动写注册表（必要时 UAC 提权）并重启自身；传 `--no-long-paths` 可跳过。

**v1 的 `backup` 怎么办？**
v2 首次运行会把根级 `backup` 自动改名为 `.backup` 并隐藏；`restore`/`list`/`clean` 同时兼容两种名字。
